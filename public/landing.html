How it works

One address for applicants. Six offices behind it.

Applicants write to one address, or straight to any office. Every agent reads and writes the same applicant file, so no one is asked for the same document twice.

01

Arrives

ask@ reads the email and any attachments, then routes it to every office it concerns.

02

Answers

Each office agent answers from its own knowledge file and the applicant's record, in parallel.

03

Replies

One combined reply goes out in the applicant's thread. A slow office follows up in the same thread.

04

Escalates

Fee waivers and questions the knowledge file cannot answer go to staff. Agents never guess.

Offices

Each office keeps its own address and its own voice.

Offices answer only what they own and sign their part of the reply. Policy lives in a knowledge file each office can read and edit.

Staff portal

A review queue, not another inbox.

Staff see only what needs a person: drafts to approve and questions to answer. An answer given once is saved to that office's knowledge, so the next applicant who asks is answered with no human.

Safeguards

Built for the inbox as it really is.

Applicant mail includes forwarded loops, spoofed senders and documents written to manipulate an AI. Each is stopped before an agent acts on it.

SIGNED

Verified webhooks

Every delivery is checked against its signature. A forged one is rejected before any agent reads it.

ONCE

No duplicate replies

Retried deliveries are recognised, so an applicant never receives the same answer twice.

LOOPS

Auto-replies ignored

Out-of-office and bounce messages are read from their headers and never answered.

SENDER

Spoofing detected

Mail that fails sender authentication is answered without touching the applicant's file.

INJECTION

Documents stay data

Instructions hidden in a PDF are quoted to staff, never followed.

APPROVAL

People decide money

Fee waivers always wait for a counselor. Nothing reaches the applicant until staff approve.
